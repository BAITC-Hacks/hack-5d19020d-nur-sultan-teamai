# WIND AGENT — начать здесь

Версия комплекта: **2.0 / 23.09.2026**. Назначение: передать ИИ-разработчику единое задание на реализацию. Это комплект спецификаций, исходных материалов и проверенного аудита, **не уже обученное приложение**.

## Как передать задание

Распакуй архив в рабочую папку coding agent, который умеет читать и создавать файлы, запускать команды и тесты и обращаться в интернет. Обычный чат без среды исполнения сможет написать код, но не подтвердить его установку и работоспособность.

Главный документ — `WIND_AGENT_MASTER_RU.md`: он содержит все нормативные разделы в одном файле. Отдельные главы в `docs/` — те же материалы для удобства. Не нужно дважды загружать оба представления в контекст. `AGENTS.md` задает постоянные правила работы. Исходные XLSX и PDF уже включены в `inputs/raw/`; предыдущие мнения находятся в `inputs/legacy_opinions/` и не являются действующими инструкциями.

Ключи передаются один раз через секреты среды / локальный `.env` по образцу `.env.example`. Не вставляй ключи в чат, Markdown, Git или README. Наличие $50 OpenAI credits и заявленных $50 NVIDIA tokens известно со слов владельца; доступ, срок действия, единицы учета NVIDIA и возможность оплачивать работу самой coding IDE не проверены.

## Текст первого сообщения coding agent

> Прочитай AGENTS.md и WIND_AGENT_MASTER_RU.md полностью. Это окончательное задание WIND AGENT v2.0; старые GPT/Claude/Gemini-тексты — только материалы аудита. Реализуй проект, а не только новый план. Создай рабочий репозиторий в project/ и последовательно выполни задачи TASKS.json. Не спрашивай подтверждение после каждого этапа. Принимай обратимые инженерные решения по defaults; научно значимые неизвестные записывай в ASSUMPTIONS.md и BLOCKERS.md. Самостоятельно проверяй официальные API и координаты из исходного PDF. Не придумывай погоду, паспорт турбины, временной пояс, фактический февраль или успешные тесты. Разрешения среды и бюджет не обходи. При блокировке одного этапа выполняй независимые этапы. Заверши все обязательные модули, unit/integration/acceptance tests, установку с нуля, replay/export, API, UI, agent traces, документацию и release-check. Сохраняй прогресс и реальные доказательства в IMPLEMENTATION_STATUS.json и RELEASE_EVIDENCE.json; при исчерпании контекста создай CONTINUE.md. Финальный ответ должен содержать действительные команды запуска, созданные артефакты, измеренные результаты и точный статус готовности, без обещаний и вымышленных метрик. Начинай с проверки входного комплекта и аудита.

## Минимальные действия владельца

Однократно предоставить среду исполнения, ключи и разрешения. При необходимости — достоверную расшифровку временных меток/координат, которую невозможно вывести из файлов. Само планирование, написание кода, тестирование и исправление ошибок не должны требовать участия владельца.

Физически отсутствующие сведения нельзя устранить более длинным промптом. Поэтому предусмотрены два честных результата: полностью работающая система с подтвержденным контрактом либо технически работающее приложение с явными ограничениями и закрытым strict-export. Второй результат нельзя переименовывать в полностью подтвержденную сдачу.
